## Project Overview

This is a Lox programming language implementation built on GraalVM's Truffle framework, developed as part of the Build Your Own Programming Language course at HPI. The implementation uses the Bytecode DSL for compilation and supports advanced features including classes, closures, and a unique array syntax.


## Architecture

### Core Components

**LoxLanguage** (`src/main/java/de/hpi/swa/lox/LoxLanguage.java`): The main Truffle language implementation. Registers built-in functions (clock, Number, String, load, round, lookup) and handles language context creation and parsing.

**LoxBytecodeCompiler** (`src/main/java/de/hpi/swa/lox/parser/LoxBytecodeCompiler.java`): Converts ANTLR parse trees to Truffle Bytecode DSL bytecode. This is the heart of the compilation pipeline. Key responsibilities:
- Variable scoping through `LoxLexicalScope` inner class
- Handles local vs global variables
- Manages closure variables (captures across function boundaries)
- Tracks function depth for proper frame materialization
- Implements Bytecode DSL operations for all Lox constructs

**Grammar** (`src/main/antlr4/de/hpi/swa/lox/parser/Lox.g4`): ANTLR4 grammar defining Lox syntax. ANTLR generates lexer/parser during Maven build into `target/generated-sources/antlr4/`.

**Bytecode Root Node** (`src/main/java/de/hpi/swa/lox/bytecode/LoxBytecodeRootNode.java`): Generated by Truffle's Bytecode DSL, defines all bytecode operations available to the compiler.

### Directory Structure

- `src/main/java/de/hpi/swa/lox/nodes/`: AST node implementations and built-in functions
- `src/main/java/de/hpi/swa/lox/runtime/`: Runtime context and data structures
- `src/main/java/de/hpi/swa/lox/runtime/data/`: Lox object representations (LoxObject, LoxFunction, LoxClass, LoxArray, LoxNumber, Nil)
- `src/main/java/de/hpi/swa/lox/parser/`: Compiler and parser logic
- `src/main/java/de/hpi/swa/lox/bytecode/`: Bytecode DSL root node
- `src/main/java/de/hpi/swa/lox/cli/`: Command-line interface
- `src/test/java/de/hpi/swa/lox/test/`: JUnit test suites

### Code Generation

The build process generates code in `target/generated-sources/`:
- `antlr4/`: Lexer and parser from ANTLR grammar
- `annotations/`: Truffle DSL-generated node implementations (suffixed with `Gen`)

### Variable Scoping System

The compiler uses a sophisticated lexical scoping system (`LoxLexicalScope`):
- **Global scope**: Variables stored in context, no parent scope
- **Local scope**: Variables stored as `BytecodeLocal` in function frames
- **Closure variables**: When inner functions reference outer function variables, tracks `functionDepth` and materializes frames for proper capture
- **Scope nesting**: Parent scope chain for proper variable resolution

Operations: `declare()`, `beginStore()/endStore()`, `loadIntoScope()`, `updateMaxFunctionDepth()`

## Lox Language Quirks

### Arrays
Uses emoji syntax instead of traditional brackets:
```lox
var a = 👉👈;        // Empty array
a👉0👈 = 1;          // Array assignment
print a👉0👈;        // Array access
print a;            // Prints: 👉1👈
```

Array literals are supported:
```lox
var a = 👉1, 2, 3👈;
```

### Self vs This
Uses `self` instead of `this` for instance references:
```lox
class A {
  printA() {
    print self.a;
  }
}
```

### Class Inheritance
Uses handshake emoji for inheritance:
```lox
class Child 🤝 Parent {
  // ...
}
```

### For Loop Condition Required
For loops must have a condition (no `break` statement exists):
```lox
for (var i = 0; i < 10; i = i + 1) {
  // condition required
}
```

### Array Iteration
Supports `for-of` and `for-in` loops:
```lox
for (var element of array) { /* ... */ }
for (var index in array) { /* ... */ }
```

### Comments
Supports both line and block comments:
```lox
// Line comment
/* Block comment */
```

### Debugging Statement
Special `halt;` statement for debugger breakpoints.

## Requirements

- Development: Oracle JDK 21, OpenJDK 21, or derivatives
- Best performance: GraalVM for JDK 21 version 21.0.4
- Build tool: Maven (via `./mvnw` wrapper)

## Bonus Features Implemented

- C3.2: REPL prints evaluated expressions
- C4.3: for-of/for-in loops for arrays
- C4.4: Array literals
- C9.1: Benchmark for array literals
- C9.2: Optimization for array literals (uses `@Variadic` annotation)
- C10.2: Array interoperability
