## Project Overview

This is a Truffle-based interpreter for the Lox programming language, built on GraalVM as part of the "Build Your Own Programming Language" course at Hasso Plattner Institute. The implementation uses GraalVM's Truffle framework to create a high-performance interpreter with JIT compilation.

## Common Commands

### Building
```bash
./mvnw package              # Compile the project
./mvnw clean               # Clean build artifacts
./mvnw antlr4:antlr4       # Regenerate ANTLR parser (usually automatic)
```

### Testing
```bash
./mvnw test                                    # Run all tests
./mvnw test -Dtest=ArrayTest                   # Run single test class
./mvnw test -Dtest=ArrayTest#testArrayAccess   # Run single test method
```

### Running Lox Programs
```bash
./lox program.lox                              # Execute a Lox file
./lox -c 'print true;'                         # Execute code string
./mvnw exec:java -Dexec.args="-c 'print 42;'"  # Alternative via Maven
```

### Debugging and Profiling
```bash
./debuglox program.lox                         # Start with Java debugger on port 5005
./lox --dap program.lox                        # Start with DAP debugger on port 4711
./lox --cputracer program.lox                  # CPU tracing
./lox --cpusampler program.lox                 # CPU sampling
./lox --cpusampler --cpusampler.Output=flamegraph --cpusampler.OutputFile=output.svg program.lox
```

### Compiler Analysis
The `lox` script supports `EXTRA_JAVA_ARGS` for GraalVM compiler options:
```bash
EXTRA_JAVA_ARGS="-Djdk.graal.TraceTruffleCompilation=true" ./lox program.lox
EXTRA_JAVA_ARGS="-Djdk.graal.Dump=Truffle:1 -Djdk.graal.PrintGraph=File -Djdk.graal.DumpPath=compiler_graphs" ./lox program.lox
```

Then analyze BGV files with:
```bash
seafoam compiler_graphs/*.bgv list           # List compilation units
seafoam compiler_graphs/file.bgv graph       # View compilation graph
```

## High-Level Architecture

### Execution Flow

1. **Parsing**: Source code → ANTLR4 parser (from `src/main/antlr4/de/hpi/swa/lox/parser/Lox.g4`)
2. **Compilation**: AST → Truffle Bytecode via `LoxBytecodeCompiler` visitor
3. **Generation**: Bytecode operations → `LoxBytecodeRootNode` (code-generated by Truffle DSL)
4. **Execution**: Bytecode node → JIT-compiled machine code by Truffle optimizer

### Key Architecture Components

**Bytecode DSL Approach**: Unlike traditional AST interpreters, this implementation uses Truffle's Bytecode DSL where operations are declared with `@Operation` annotations in `LoxBytecodeRootNode.java`. Each operation has multiple `@Specialization` methods for different type combinations, enabling efficient type-specialized dispatch.

**Hybrid Node System**: Complex operations (function calls, property access, built-ins) use traditional Truffle nodes in `src/main/java/de/hpi/swa/lox/nodes/`, while simple operations (arithmetic, logic) are handled directly in bytecode.

### Package Structure

- **`src/main/antlr4/de/hpi/swa/lox/parser/`**: ANTLR4 grammar defining Lox syntax
- **`src/main/java/de/hpi/swa/lox/`**:
  - `LoxLanguage.java`: Main language registration (`@TruffleLanguage.Registration`)
  - **`cli/`**: Command-line launcher (`LoxMain.java`)
  - **`bytecode/`**: Bytecode operations and root node (`LoxBytecodeRootNode.java` with `@GenerateBytecode`)
  - **`nodes/`**: Truffle nodes for complex operations (calls, properties, built-ins)
  - **`parser/`**: ANTLR visitor that compiles AST to bytecode (`LoxBytecodeCompiler.java`)
  - **`runtime/`**:
    - `LoxContext.java`: Global execution context and built-in function registry
    - **`data/`**: Runtime data types (LoxArray, LoxObject, LoxClass, LoxFunction, etc.)
- **`src/test/java/de/hpi/swa/lox/test/`**: JUnit tests using Polyglot Context API

### Truffle Concepts Used

- **Bytecode DSL**: `@GenerateBytecode`, `@Operation`, `@Specialization`, `@ShortCircuitOperation`
- **Node Specialization**: `@Cached`, `@TruffleBoundary` for optimization
- **Frame Management**: `FrameDescriptor`, `MaterializedFrame` for closures
- **Object Model**: `DynamicObject`, `Shape` for optimized property storage
- **Polyglot Interop**: `InteropLibrary` for cross-language support
- **Instrumentation**: Statement/expression/variable tags for debugging

## Language-Specific Features

### Custom Array Syntax
Uses emoji delimiters instead of brackets:
```lox
var arr = 👉1, 2, 3👈        // Array literal
print arr👉0👈;              // Access: prints 1
arr👉1👈 = 42;               // Assignment
```

Implementation: Grammar defines `👉` and `👈` tokens; `LoxArray.java` provides runtime support with InteropLibrary.

### Self Instead of This
Classes use `self` keyword:
```lox
class Counter {
  increment() {
    self.count = self.count + 1;
  }
}
```

Implementation: `LoxFunction` stores `self` field (LoxObject reference); methods receive implicit self binding.

### For Loop Condition Required
Unlike standard Lox, for loops must have a condition (no `break` statement exists):
```lox
for (var i = 0; i < 10; i = i + 1) { ... }  // Condition required
```

### Class Inheritance Syntax
Uses `👉👈` instead of `extends`:
```lox
class Child 👉👈 Parent {
  method() {
    super.method();
  }
}
```

### Built-In Functions
Global scope provides:
- `clock()`: Current time in seconds
- `Number(value)`: Type conversion to number
- `String(value)`: Type conversion to string
- `load(path)`: Load and execute external Lox file
- `round(number)`: Mathematical rounding
- `lookup(object, key)`: Dynamic property access

## Development Workflow

### Adding New Operations

1. Add `@Operation` static class in `LoxBytecodeRootNode.java`
2. Define `@Specialization` methods for type combinations
3. Update `LoxBytecodeCompiler.java` to emit the operation
4. Rebuild with `./mvnw package` (triggers Truffle DSL code generation)

### Modifying Grammar

1. Edit `src/main/antlr4/de/hpi/swa/lox/parser/Lox.g4`
2. Run `./mvnw antlr4:antlr4` (or just `./mvnw package`)
3. Update `LoxBytecodeCompiler.java` visitor methods
4. Add tests in `src/test/java/de/hpi/swa/lox/test/`

### Adding Built-In Functions

1. Create node class extending `BuiltInNode` or `BuiltInNodeWithArgs` in `nodes/`
2. Register in `LoxContext.initializeBuiltins()`
3. Test via `AbstractLoxTest.eval()` helper

### Debugging Tips

- Java debugging: Use `./debuglox` and attach VSCode to port 5005
- Lox debugging: Use `./lox --dap` and attach VSCode to port 4711
- Compilation tracing: `EXTRA_JAVA_ARGS="-Djdk.graal.TraceTruffleCompilation=true" ./lox`
- Inlining analysis: Add `-Djdk.graal.TraceTruffleInlining=true`
- Graph dumps: Add `-Djdk.graal.Dump=Truffle:1 -Djdk.graal.PrintGraph=File`

### Migration from Standard Lox

Use provided scripts to convert standard Lox syntax:
- `./migration_boring_lox_to_amazing_lox.sh` (Linux/Windows)
- `./migration_boring_lox_to_amazing_lox_macos.sh` (macOS)

Converts: `this` → `self`, `[]` → `👉👈`, `extends` → `👉👈`

## Bonus Challenges Implemented

- **C3.2**: REPL prints evaluated expressions (not just statements)
- **C4.3**: for-of/for-in loops for array iteration
- **C4.4**: Array literals with `👉👈` syntax
- **C9.1**: Benchmark for array literals (documented in `bonusOptimizations/arrayLiterals/`)
- **C9.2**: Array literal optimization (reduces intermediate array allocations)
- **C10.2**: Array interoperability via Truffle's InteropLibrary
